# 站点

平台作为一个网站对外提供时的行为：挂在什么地址下、怎么经反向代理对外、在公网上有哪些限制、素材怎么缓存。局域网里直接打开服务器端口（页面-3）是这里的特例。

### 站点-1 挂在任意路径下

- 平台的页面在同一层：首页 `./`（房间页，或只有一局时的对局页）、对局页 `./play`、房间页 `./room`。页面用到的其余地址都在页面旁边：页面文件 `static/`、模块 `m/`、kit `k/`、素材 `assets/`，大厅与对局的 WebSocket `lobby`、`battle`。
- 页面里的每个地址都按页面自己的地址取相对路径，样式表里的（字体）按样式表的地址，不从站点根目录写起；WebSocket 的地址同样按页面的地址取，`http:` 的页面用 `ws:`，`https:` 的页面用 `wss:`。
- 服务器改写模块里的导入（裸模块名，以及 kit 对引擎模块的导入）时，写成相对于这个模块自己地址的路径。
- 所以平台可以直接挂在根目录（`https://ig.example/`），也可以挂在反向代理的一个子路径下（`https://example/icebreaker/`）：代理把这个前缀去掉后转给服务器（含 WebSocket 升级），服务器不需要知道前缀，前缀之外什么也不请求。

- 来源：设计决定：同一域名下已有别的游戏用了根路径的 `/lobby` 等地址（部署记录），平台要能和它们共用一个域名

### 站点-2 公网上的限制

- **按网络地址**：一个地址同时最多保持 24 条 WebSocket（大厅与对局合计）；再多的升级请求回 429，不建立连接，关掉一条就空出一个位置。一个地址一分钟内最多输错 10 次房间编号（没有这个房间）；之后这一分钟里它的加入请求不再查找房间，只提示「操作过于频繁，请稍后再试」。
- **整台服务器**：同时最多 500 个房间、100 局对局（默认值；启动参数 `--max-rooms`、`--max-battles` 可以改，只接受不小于 1 的整数）。房间满时创建房间提示「当前服务繁忙，请稍后再试」；对局满时开赛失败，房间回到项目调整。
- **网络地址**：默认是连接的对端地址。服务器在反向代理后面时以 `--trust-proxy` 启动，地址取代理给的 `X-Real-IP`；代理必须把这个头改写成它自己看到的地址（不能原样转发客户端给的），否则谁都能冒充任何地址。

- 来源：设计决定；两句提示取自活动表 `constToastData` 的 `continuousClicks`、`serverOverload`（`activity_table.json` 的 `MULTIPLAY_V3/act1multi`）

### 站点-3 素材的缓存

- 服务器启动时按素材目录里每个文件的路径、大小和修改时间算出素材的版本号（12 位十六进制）。页面在 `<meta name="ig-assets">` 里写明素材从 `assets/~<版本号>/skeleton/` 取，页面里的素材地址都从这里起算。
- `assets/~<版本号>/…` 和 `assets/…` 是同一个文件。版本号是当前的时，回复允许浏览器和代理保存一年、期间不再校验；版本号不对（服务器换了素材以后，旧页面还在请求旧版本）时照样给当前的文件，但不允许保存。
- 页面、页面文件和不带版本号的素材每次都向服务器（或代理的缓存）校验（强 ETag，未变时回 304）；代理缓存它们时，部署之后清掉。脚本和 kit 见 站点-4。
- 没有素材目录时页面写 `assets/skeleton/`。

- 来源：设计决定：素材有几百兆，玩家每次打开页面都逐个校验会很慢；带版本号的地址只在素材变了以后才换

### 站点-4 脚本的缓存、预加载与压缩

- **代码的版本号**：服务器按它在 `/m/` 下提供的各个包——工作区的包每个文件的路径、大小和修改时间，安装的第三方包的 package.json——算出代码的版本号（12 位十六进制），距上次计算超过两秒时重算；发布包的文件不变，版本号也不变。
- **带版本号的地址**：`m/~<版本号>/…` 和 `m/…` 是同一个模块，`k/~<版本号>/…` 和 `k/…` 是同一个 kit 文件；kit 在带版本号的地址下引用同一版本号下的兼容模块，与页面的模块是同一份。版本号是当前的时，回复允许浏览器和代理保存一年、期间不再校验；不是当前的时照样给当前的文件，但不允许保存。页面的模块脚本、Worker 和 kit 都从带版本号的地址取：页面写进当前的版本号，模块从自己的地址得知版本号。
- **预加载**：服务器发页面时，在 `</head>` 前为页面的每个模块脚本静态引用到的全部模块（任意层，广度优先，各一次；JSON 文件按它的脚本算，不含动态引用的）写一条 `<link rel="modulepreload">`，浏览器一开始就同时请求它们，不必等上一层到了才知道下一层。
- **JSON 模块按脚本发**：模块用 `import … with { type: 'json' }` 引用 JSON 文件时，服务器发出的模块改为引用 `….json.js`，不带导入属性；`….json.js` 是那个 JSON 文件的脚本（`export default JSON.parse(…)`），和其他模块一样缓存、预加载。导入属性要 Chromium 123 起才认识，更早内核的浏览器（不少手机自带的浏览器）读到它整页脚本都不运行。
- **加载画面**：服务器把页面引用的加载画面的样式（`static/boot.css`）和脚本（`static/boot.js`）直接写进页面（页面-8），它们不再单独请求。
- **压缩**：1 KiB 以上的文本、JSON、JavaScript 和 SVG，客户端接受时压缩后发送（brotli 优先于 gzip），带 `Vary: Accept-Encoding`，每种编码各有自己的 ETag（两个 ETag 都可以拿来校验）；压缩在事件循环之外进行，结果按 ETag 保留（最多 256 MiB）。

- 来源：设计决定：页面的脚本有两三百个模块，逐层发现、每次逐个校验在远处很慢；按引擎和平台的文件算版本号，代码一变地址就变；JSON 按脚本发是因为 2026-10 的访问记录里，HeyTap、小米、QQ 浏览器等内核低于 Chromium 123 的浏览器打开页面后从未连上大厅（加载停在 30%）

### 站点-5 一场对局的特效包

- 素材里的攻击特效包（`fx/units.json`）带查询参数 `for=<内容键,…>`（干员按角色 ID，敌人、装置按键；逗号分隔，最多 256 个，每个由字母、数字和下划线组成，至多 64 个字符）时，服务器回这些单位的特效包（引擎 渲染-10 的「一场对局的包」），版本号的规则同 站点-3；参数不合格回 400，没有特效包回 404。不带参数时照旧是整包。
- 服务器第一次需要时读一次整包并建好引擎的索引（之后不再保留解析后的整包），文件变了时重读；最近 64 个答复按参数保留。
- 对局页按本局的单位请求特效包，只载入本局用到的贴图（引擎 渲染-23）；模型、装置、地图拼件、特效和贴图同时载入。

- 来源：设计决定：整包有一千多个特效、27 MB，一场对局只用到其中百来个（约 2 MB）

### 站点-6 几台节点

同一个服务器可以同时跑在几台机器上，每台是一个节点，各有自己的房间和对局，彼此不同步。服务器进程的环境给出节点：

- `NCN_GAME_DIGIT`：这台节点的编号，1–9；
- `NCN_GAME_PEERS`：每台节点的编号和主机名，如 `1=a.example.org,2=b.example.org`（包括这台）。

两项都没有时服务器自成一台，同以前一样；值不合格时也自成一台，并在日志里说明原因。

- **房间编号**：节点上新开的房间（包括快速匹配开的），编号的第一位是这台节点的编号，后五位随机，仍是 6 位数字（房间-1）。
- **别的节点的房间**：输入的编号第一位是名单里另一台节点的编号时，服务器不当作输错的编号（不计入 站点-2 的次数），而是回 `{ t: 'elsewhere', code, host }`：那台节点的主机名和这个编号。
- **页面跟过去**：房间页收到后，只在主机名是页面自己域名下一级的名字时（页面在 `play.example.org`，节点是 `<节点>.play.example.org`）把大厅连接改连那台节点（路径不变），连上后自动加入这个编号；本标签页记住这台节点，直到房间关闭。其他主机名不连，提示从游戏入口页进入后再加入。
- **对局**：开赛时去对局页的地址带上 `server=<节点>`，对局页的连接连到那台节点；「回到比赛」同样带上。页面本身、素材和本地存储仍在页面自己的域名下，所以各节点要部署同一个版本。

- 来源：设计决定：玩家按所在地区连到最近的节点，同一房间的两名玩家要连同一台

### 站点-7 数据 mod

服务器开服时读一次 mod 文件夹，叠到官方内容上（引擎 mod-3），不热更新：

- **文件夹**：启动参数 `--mods <文件夹>`，没有时用环境变量 `AUE_MODS_DIR`，再没有时用根目录下的 `mods`；文件夹不存在时没有 mod。文件夹里每个含 `pack.json` 的子文件夹是一个 mod，按名字排序，读法同引擎的 `aue mod check`（引擎 mod-12）。
- **日志**：开服时写出每个 mod：加载了（加了几条、改了几条记录），或没有加载和每个问题；警告和冲突；最后一行列出加载了的 mod 和文件夹。
- **对局**：房间里的对局用这份内容（引擎 mod-8），对局内容因此带上 mod 的 id、版本和 sha256，进入内容哈希。
- **列表和文件**：`GET /mods/index.json` 回主机的列表（引擎 mod-10，没有 mod 时 `mods` 为空）；`GET /mods/<mod id>/<路径>` 只回列表里写的数据文件，内容是开服时读到的；`/mods/` 下的其他路径回 404，只接受 GET 和 HEAD。
- 几台节点（站点-6）要装同一份 mod。

- 来源：设计决定，见引擎 ADR 0064、ADR 0037（mod 装在主机上，开服时加载一次；握手比对内容哈希）；Stronghold Protocol 的 `docs/PACKS.md` §4「Server-side only for gameplay」
